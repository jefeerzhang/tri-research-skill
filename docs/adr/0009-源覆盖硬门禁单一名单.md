# 源覆盖硬门禁单一名单（R-A）

SKILL / README / `report-format.md` 写「六个搜索后端」且硬门禁条款写「点名六源」，但 `validate_report.py` 的「搜索源使用」行机器名单只有五名（AnySearch / SciVerse / Exa / SerpApi / WebSearch），Tavily 被文档当成可并入说明的第六源。审计 P0-1：文档六源、代码五源，Agent 漏写 Tavily 仍能 `DONE`。决定：执行情况「搜索源使用」行的点名名单以 `validate_report.USAGE_ROSTER` 为**唯一机器真源**，采用 **R-A**——六源全点名（AnySearch / SciVerse / Exa / SerpApi / Tavily / WebSearch）；Tavily 仍是 `optional`，未用或静默跳过须写 `0/跳过`，不得省略该名。本 ADR 只收口点名名单，不改变 `BackendRequirementLevel`（Exa / SciVerse / SerpApi 仍 `required`，AnySearch `recommended`，Tavily / WebSearch `optional`）。

## Considered Options

- **维持文档六源 / 代码五源**：被拒——两处真源已证明会漏；「Tavily 可并入说明」让验收器无法拦漏写。
- **把 Tavily 升为 `required`**：被拒——R-A 只要求点名，不要求实际调用；升档会堵死无 Key 的冷启动，且超出本波（W0）范围。
- **文档改回五源、代码不动**：被拒——能力边界表与 `来源:` 词汇已含 Tavily，缩名单等于承认第六源是装饰。
- **（采用）R-A：单一机器名单 = 六源全点名，optional 可记 0/跳过**：文档、验收器、合约测试共读同一元组；漏写 Tavily 与漏写 Exa 同等失败。

## Consequences

- `USAGE_ROSTER`（`REQUIRED_SOURCE_BACKENDS` 为其向后兼容别名）含六名；注释不得再把 Exa 写成 optional。
- SKILL 硬门禁、skill README、`references/report-format.md`、`test-prompts.json` 的点名列表与代码元组对齐；禁止「五名称为验收必填」。
- 合约测试钉住：SKILL 硬门禁行抽出的源名集合 = `USAGE_ROSTER`；一侧改名/删名，CI 红。
- 未用的 optional 源（Tavily / WebSearch）写 `0`、`0条` 或 `跳过` 均合法——门禁只验点名，不验计数，也不对账 Evidence Ledger（ADR-0005 / ADR-0010 另案）。
- 不在本 ADR 落地：SerpApi 安装捆绑（ADR-0012）、证据自动入账（ADR-0010）、Registry / SciVerse Backend 重构。
