# 检索成功路径与证据台账因果绑定（W1）

ADR-0005 把 Evidence Audit 做成 `done` 硬门禁，但检索成功与台账写入仍是两段 Agent 纪律：Machine 后端 CLI 可以搜完即 exit 0，Lead 漏记 `evidence.py add` 时要到 `done` 才红。审计 P0-2：成功搜索与 `seen` 行无因果绑定。决定：CLI 成功路径**可选**经 `--session` 绑到 Evidence Ledger——有 `--session` 时，`search` / `batch_search` 成功后自动 `append_records(kind=seen, backend/query/url/title/ts)`；**台账写入失败则 CLI 非零退出**（不得带着未入账的成功结果继续）。无 `--session` 保持裸搜（测试 / 临时探活）。本波只改仓内 Machine 后端（Exa / Tavily / SerpApi）；AnySearch / SciVerse / WebSearch 不改外部包，SKILL 给标准登记模板。Audit 算法不变（仍是 ADR-0005 的 `audit_report`）；本 ADR 只加强**输入通道**。

## Considered Options

- **检索成功后仍只靠 Lead 手记（维持 ADR-0005 收窄一）**：被拒——漏记成本转到 `done`，Agent 在主路径上会把「搜到了」当成「入账了」。
- **无 `--session` 也强制入账（改默认、打断现有测试/探活）**：被拒——裸搜是测试与 ad-hoc 的合法入口；研究主路径由 SKILL 强制传 `--session`，不必堵死无会话调用。
- **台账失败仍 exit 0、只 stderr 警告**：被拒——用户锁定 fail-closed：写入失败不得返回成功。
- **本波挂钩 AnySearch / SciVerse / WebSearch 外部包**：被拒——外部包不在本仓契约内；模板 + 合约测试钉住登记句即可，自动挂钩留待后续波次。
- **（采用）`--session` 可选绑定 + 写入失败阻断 CLI + External 仅模板**：Machine 三后端共一个 helper 调现有 `evidence.append_records`，不另造台账格式；不改 `audit_report`。

## Consequences

- Exa / Tavily / SerpApi 的 `search` 与 `batch_search` 增加 `--session`（及 `--state-dir`）；成功路径先入账再打印结果。
- 无 `--session`：行为与现网一致，不写台账。SKILL 写明 Lead 研究主路径**必须**传 `--session`；裸搜不是研究主路径。
- 写入失败（会话不存在 / 已封账 / IO）→ JSON `{"error": …}` + exit 1。空结果且无合法 URL 时无可写行，不视为写入失败。
- External 源继续 `evidence.py add` 模板；`user_provided` 仍手记。
- 不在本 ADR 落地：ADR-0011 / 0012 / 0013、`audit_report` 算法、SerpApi 安装捆绑、architecture.json 重绘。
- **部分被 ADR-0013 演进**：能力类上 WebSearch 是 Host、AnySearch / SciVerse 是 External Tool；本 ADR 的「External」仅指非 Machine CLI `--session` 的台账输入通道，入账语义不改。
- 测试：假搜索 + `--session` 写出台账行；写入失败非零；无 `--session` 不要求写台账；合约测试钉住 SKILL 模板与 ADR 短语。
