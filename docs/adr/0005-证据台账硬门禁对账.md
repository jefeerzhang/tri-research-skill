# 证据台账硬门禁对账：报告引用必须溯源到会话台账

`validate_report.py` 只验格式（章节、URL 唯一、双语），查不出编造文献——SKILL.md 第六步的 SciVerse DOI 核验、网页 `extract` 抽查全是推荐流程，Agent 跳过不红。本 ADR 记录 Evidence Ledger（会话级证据台账）落地时的三个真权衡：对账强度、存储形态、指纹边界。

决定：新 `scripts/evidence.py`（`add` / `list [--summary]` / `audit`）管理每会话一个 append-only 的 `{session_id}.evidence.jsonl`；`done` 在报告验证通过后执行 Evidence Audit——报告每条引用 URL 经与 `validate_report` 同一套归一化（`canonicalize_url`）后必须在台账命中，untraced 即 `StateError`；DONE proof 追加台账快照指纹（`evidence_lines` + `evidence_sha256`），`check` 的 INTEGRITY 双验报告与台账。登记由 Lead 统一完成（`seen` 记 backend/query/url/title/ts，`user_provided` 记 url/note/ts），写入不去重。

## Considered Options

### 对账强度

- **软提示（`UNTRACED:3` warning 不拦截）**：被拒——对账退化成又一个「推荐流程」，与项目「可机器检查的硬门禁」哲学冲突（6.3.1 已刻意收缩过一次文档承诺，不能再往回走）。
- **独立可选项（`validate_report --trace-ledger`，不进 `done`）**：被拒——「验收器能单独跑」与「done 必须过」本就不冲突，单独命令弱化完成标准的约束力。
- **（采用）`done` 硬门禁，无豁免开关**：豁免路径一旦存在，Agent 遇麻烦必走捷径，台账可信度整体崩塌。合法例外的唯一正道是登记 `user_provided` 行——豁免动作本身进台账，审计仍闭环。漏记的修复成本极低（补登记 → 重跑 `done`，与 validate 失败的 FIX 循环同手感）。

### 存储形态

- **塞进 state JSON**：被拒——登记是高频小写入，state JSON 是低频结构变更；混在一起每次登记都要全量锁加重写全文件，且证据流水与「报告 SHA-256、history」等严肃字段混在一个文件里，语义脏。
- **（采用）每会话独立 JSONL，append-only**：追加一条不用重写全文件；崩溃最多留半行（读取时末行容错丢弃、中部损坏显式报错）；「证据只被发现、不被改写」与台账语义天然吻合。登记复用现有 per-session `session_lock`，不发明新锁。

### 指纹边界（INTEGRITY 覆盖什么）

- **不管（v1 接受「done 后补台账」口子）**：被拒——项目刚在 6.6.0 修完「`INTEGRITY:OK` 假闭环」，台账作为新验收依据若不进指纹体系，就是新版的假闭环。
- **done 后锁死台账**：被拒——`add_dimensions` 本来就允许 DONE 后继续研究再重新 `done`，「焊死/解锁」是无谓的新状态机概念。
- **（采用）proof 记台账快照指纹，EXTENDED 重跑 `done` 自然刷新**：指纹防的是**事后无感知篡改**，不是「防一切」——补一条假记录再重跑 `done` 这个口子任何硬门禁都有（报告同理可改），防线在「每次 `done` 都要重新通过全部验收」。

## Consequences

- 报告里的引用可机器回答「在哪次搜索见过」；`audit` 失败时全量打印 `[编号] URL`，Agent 补登记即可恢复。
- **行为收窄一**：`Runtime WebSearch` 等不走 CLI 的源也要 Agent 显式登记（AnySearch / SciVerse 本就是外部调用，无自动拦截可能；自动登记双轨留待有真实需求再做）。
- **行为收窄二**：schema v3 旧 DONE 会话 `check` 报 corrupt（proof 无台账字段），需 `add_dimensions` + 重跑 `done` 重建。
- `StateError` 下沉 `_common.py`：evidence 与 state_machine 互相 import，双加载形态下异常类必须单副本（回归测试钉住「ERROR: 行、无 traceback」契约）。
- v1 不对账「搜索源使用」行——`list --summary` 供照抄即可，后续可纯增量纳入 audit。
- 测试：`tests/test_evidence.py`（写入/翻阅/容错/封账/审计/指纹/并发），`tests/test_state_machine.py::ReportIntegrityCheckTests` 等 6 个文件的 done 路径补登记 seam（`_test_helpers.register_report_evidence`）。
